The asset stays stable. Its versions carry the detail.

A conceptual map of the core metadata. Table names follow the source: “videos” contains both video and still-image assets.

Creative metadata belongs to an exact version. It includes model, prompt, source label/date, notes, release information and typed custom fields. Optional grid-image and reference-image IDs point to other image versions within the same project. This object is embedded in assetVersions, not a separate table.

Review state belongs to the asset. Status, rating, shortlist and tags sit on the asset. Comments point to the asset, with optional video timecodes; this schema does not attach comments to a version. The current-version pointer selects which take is active.

This is a focused ER view. Projects can contain root-level assets and nested folders. Membership, upload sessions, media jobs, review links, imports, and sync queues are omitted for readability. The media-flow view explains their role in delivery.
